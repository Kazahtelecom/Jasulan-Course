# Архитектура платформы Web-OOP (Clean Architecture & Sandbox)

## 1. Введение и обзор системы

Платформа **Web-OOP** представляет собой локальную интерактивную мини-LMS, спроектированную для практического изучения объектно-ориентированного программирования студентами 2 курса специальности «Программная инженерия» КазНУ им. аль-Фараби.

Ключевой архитектурный фокус системы — **автономность, простота локального развертывания и надежная изоляция выполнения студенческого кода** без необходимости использования тяжеловесных инструментов сборки фронтенда (Zero-Build принцип).

---

## 2. Слои приложения (Clean Architecture)

Проект строго следует принципам разделения ответственности Clean Architecture:

```
┌─────────────────────────────────────────────────────────┐
│                    Пользователь (UI)                    │
│      Vanilla JS + Tailwind CSS CDN + Mermaid.js CDN     │
└────────────────────────────┬────────────────────────────┘
                             │ HTTP / JSON
┌────────────────────────────▼────────────────────────────┐
│              Транспортный слой (Routers)                │
│    app/routers/health.py  •  app/routers/runner.py      │
└────────────────────────────┬────────────────────────────┘
                             │ Вызовы сервисов и ORM
┌────────────────────────────▼────────────────────────────┐
│                Слой логики (Services)                   │
│   app/services/ast_validator.py • app/services/runner.py │
└─────────────┬─────────────────────────────┬─────────────┘
              │                             │
┌─────────────▼───────────────┐ ┌───────────▼─────────────┐
│    Изоляция (Sandbox OS)    │ │   Слой данных (Data)    │
│  tempfile.TemporaryDirectory│ │  app/models/ (Student,  │
│  subprocess.run(pytest, 5s) │ │  TopicProgress, Subm.)  │
└─────────────────────────────┘ └───────────┬─────────────┘
                                            │ SQLAlchemy
                                ┌───────────▼─────────────┐
                                │   SQLite Storage        │
                                │   data/web_oop.db       │
                                └─────────────────────────┘
```

### 2.1 Слой представления (Zero-Build Frontend)
- **Каталог:** `app/templates/`, `app/static/`
- **Технологии:** HTML5, Jinja2, Tailwind CSS (CDN), Mermaid.js (CDN), Vanilla JavaScript.
- **Особенности:** В репозитории отсутствуют файлы `package.json`, `package-lock.json` и каталог `node_modules`. Все стили и скрипты подключаются напрямую через доверенные CDN либо поставляются в виде легковесных статических файлов (`app.js`, `style.css`).

### 2.2 Транспортный слой (API Routers)
- **Каталог:** `app/routers/`, `app/main.py`
- **Технологии:** FastAPI, Starlette, Pydantic 2.
- **Ответственность:**
  - Валидация входных HTTP-запросов и сериализация ответов.
  - Эндпоинт `GET /api/health` — комплексный опрос здоровья компонентов (FastAPI, SQLite, RunnerService).
  - Эндпоинт `POST /api/runner/smoke` — проведение дымового теста изолированной песочницы.
  - Точка входа `app/main.py` осуществляет жизненный цикл приложения (`lifespan`), монтирует статику и инициализирует схему БД.

### 2.3 Слой сервисов (Business Logic & Sandbox)
- **Каталог:** `app/services/`
- **Компоненты:**
  - `ASTValidator`: статический анализатор синтаксического дерева Python. Проверяет код студента перед запуском на предмет запрещенных импортов и опасных вызовов.
  - `RunnerService`: координатор изолированного исполнения. Создает защищенную временную директорию, генерирует файлы `solution.py` и `test_solution.py`, запускает `pytest` через отдельный процесс операционной системы с ограничением по времени и собирает диагностический вывод.

### 2.4 Слой данных (Models & Database)
- **Каталог:** `app/models/`, `app/database/`
- **Технологии:** SQLAlchemy 2.0 (декларативные модели с типизацией `Mapped`, `mapped_column`), SQLite.
- **Сущности:**
  - `Student`: профиль учащегося (`id`, `username`, `full_name`, `created_at`).
  - `TopicProgress`: прогресс освоения темы (`student_id`, `topic_id`, `is_completed`, `score`, `updated_at`).
  - `Submission`: попытка решения задания (`student_id`, `task_id`, `code`, `status`, `test_output`, `created_at`).

## 3. Механизм работы песочницы RunnerService

Процесс проверки студенческого решения состоит из следующих этапов:

1. **Предварительный AST-аудит:**
   - Модуль `ASTValidator` парсит код решения через `ast.parse()`.
   - Если код содержит синтаксическую ошибку или запрещенные конструкции (импорты `os`, `sys`, `subprocess`, `shutil`, `socket` или вызовы `eval`, `exec`), выполнение немедленно прерывается со статусом `SECURITY_VIOLATION`. Дочерний процесс операционной системы не создается.
2. **Изоляция в файловой системе:**
   - Создается изолированный временный каталог через `tempfile.TemporaryDirectory`.
   - Внутри каталога создаются файлы:
     - `solution.py` — код студента.
     - `test_solution.py` — сьют тестов для проверки задания.
3. **Исполнение тестов через pytest:**
   - Запускается дочерний процесс: `[sys.executable, "-m", "pytest", "test_solution.py", "-v"]`.
   - Рабочей директорией (`cwd`) процесса назначается созданный временный каталог.
   - Устанавливается жесткий таймер ожидания: `timeout = 5.0` секунд.
4. **Обработка результатов:**
   - При успешном завершении (`returncode == 0`): статус `PASSED`.
   - При провале ассертов тестов (`returncode != 0`): статус `FAILED`.
   - При превышении таймаута (`subprocess.TimeoutExpired`): статус `TIMEOUT`.
5. **Гарантированная очистка ресурсов:**
   - В блоке `finally` временный каталог удаляется. При возникновении временных блокировок файловых дескрипторов под Windows процесс принудительно освобождает ресурсы.

## 4. Модель угроз и безопасность

| Потенциальная угроза | Вектор атаки | Архитектурная защита |
|---|---|---|
| **Выполнение системных команд** | Студент пытается вызвать `os.system("rmdir /s /q ...")` или `subprocess.Popen(...)` | `ASTValidator` блокирует импорты `os`, `sys`, `subprocess`, `shutil`, `socket` на этапе статического разбора. |
| **Динамическое выполнение строк** | Использование `eval("...")` или `exec("...")` для скрытого вызова функций | `ASTValidator` запрещает вызовы встроенных функций `eval`, `exec`, `__import__`. |
| **Отказ в обслуживании (DoS)** | Бесконечный цикл `while True: pass` или глубокая рекурсия | Жесткий лимит `timeout=5.0s` в `subprocess.run` гарантированно прерывает процесс. |
| **Утечка данных между студентами** | Чтение чужих файлов решений на диске | Каждый запуск выполняется в уникальной изолированной директории `TemporaryDirectory`, удаляемой после прогона. |
| **Уязвимости npm-зависимостей** | Заражение через скомпрометированные npm-пакеты фронтенда | Zero-Build: в проекте нет `node_modules` и npm-пакетов; статика отдается напрямую. |
