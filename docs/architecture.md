# Архитектура платформы Web-OOP (Clean Architecture, WeekModule & Sandbox)

## 1. Введение и обзор системы

Платформа **Web-OOP** представляет собой локальную интерактивную мини-LMS, спроектированную для практического изучения объектно-ориентированного программирования студентами 2 курса специальности «Программная инженерия» КазНУ им. аль-Фараби.

Ключевой архитектурный фокус системы — **модульность, чистота кода (SRP), независимость недель через WeekModule, Zero-Build фронтенд и надежная изоляция студенческого кода** без необходимости использования сторонних тяжеловесных контейнеров на хосте (Zero-Build & Native Python Isolation).

## 2. Слои приложения (Clean Architecture)

Проект строго следует принципам разделения ответственности Clean Architecture:

### 2.1 Слой представления (Decomposed Zero-Build Frontend)
- **Каталог:** `app/templates/`, `app/templates/components/`, `app/static/`
- **Компоненты шаблонов:**
  - `components/header.html`: Шапка с селектором 4 студентов, индикатором зачета и переключателями недель/вкладок.
  - `components/tab_home.html`: Обзор недели, карточка Hero и 3-этапная воронка обучения.
  - `components/tab_theory.html`: Лекция с визуальными карточками и кнопкой отметки прочтения теории.
  - `components/tab_practice.html`: Интерактивный тренажер с построчным разбором и кнопкой готового решения.
  - `components/tab_quiz.html`: Итоговый тест из 10 вопросов (100% оценки недели).
  - `components/tab_results.html`: Детализированная сводка баллов и прогресс-бар.
- **Особенности:** Zero-Build, отсутствие `node_modules`. `app.js` модулирован по зонам ответственности (UI Navigation, Student State, Practice Runner, Quiz Evaluation, Progress Sync).

### 2.2 Модульный слой контента (WeekModule & Registry)
- **Каталог:** `app/modules/`, `app/content/week_1/`, `app/content/week_2/`, `app/content/week_3/`
- **Интерфейс:** Контракт `WeekModule` инкапсулирует номер недели, название, обзор, секции теории, практические задачи, вопросы квиза и функцию валидации ответов.
- **Иерархия контента:** Контент каждой недели инкапсулирован в отдельном пакете `app/content/week_X/` (`theory.py`, `practice.py`, `quiz.py`), регистрируемом в `app/modules/registry.py`.
- **Реестр:** `WeekRegistry` централизованно хранит модули недель. Неделя 3 (Паттерны GoF и Чистая архитектура) интегрирована декларативно без дублирования бизнес-логики.

### 2.3 Транспортный слой (API Routers)
- **Каталог:** `app/routers/`
- **Обобщенный роутер `weeks.py`:** Предоставляет универсальные обработчики для запуска тренажера, проверки квизов и отметки теории для любой зарегистрированной недели.
- **Тонкие делегаты `week1.py`, `week2.py` и `week3.py`:** Сохраняют 100% обратную совместимость для существующих URL-путей (`/week1`, `/week2`, `/week3`, `/api/week1/...`, `/api/week2/...`, `/api/week3/...`), исключая дублирование кода.
- **Роутер студентов `scoring.py`:** Управляет списком 4 студентов (`zhasulan`, `roman`, `arseniy`, `saubakirov`), передачей контекста через `X-Student-Id` и безопасным чтением прогресса (строго read-only, без нежелательных `commit`).

### 2.4 Слой безопасности и песочницы (RunnerService & AST Whitelist)
- **Каталог:** `app/services/`
- **Строгий синтаксический белый список AST (`ASTValidator`):**
  - Ограничение размера кода до 15 КБ (отсечение DoS до синтаксического анализа).
  - Белый список типов узлов AST (`ALLOWED_NODE_TYPES`).
  - Белый список модулей (`math`, `typing`, `abc`, `random`, `datetime`, `collections` и др.).
  - Блокировка вызовов `eval`, `exec`, `open`, `compile`, `getattr`, `setattr`, `__import__`.
  - Блокировка системных атрибутов (`__class__`, `__subclasses__`, `__dict__`, `__globals__`).
- **Изолированный запуск процесса (`RunnerService`):**
  - Запуск через `python -I` (изолированный режим без доступа к пользовательскому `sys.path` и переменным `PYTHON*`).
  - Очищенные переменные окружения (`safe_env`).
  - Временная папка `tempfile.TemporaryDirectory` с принудительным `timeout = 5.0` секунд.

## 3. Модель угроз и безопасность

| Потенциальная угроза | Вектор атаки | Архитектурная защита |
|---|---|---|
| Побег из песочницы через `__subclasses__` | Интроспекция классов `().__class__.__subclasses__()` | AST Whitelist блокирует доступ к любым системным атрибутам с двойным подчеркиванием (кроме разрешенных ООП-методов) |
| Чтение системных файлов хоста | `open()`, `pathlib.Path()`, `importlib` | AST Whitelist блокирует функцию `open` и модули `pathlib`, `importlib`, `os`, `sys`, `subprocess` |
| Выполнение динамического кода | `eval()`, `exec()`, `compile()`, `getattr()` | Полная блокировка вызовов в ASTValidator |
| Зависание сервера (DoS бесконечным циклом) | `while True: pass` | Принудительный таймаут subprocess (5.0 сек) со статусом `TIMEOUT` |
| DoS парсера гигантским пейлоадом | Отправка мегабайтного файла с кодом | Проверка размера до парсинга AST (жесткий лимит 15 КБ) |
| Коллизия баллов студентов через Cloudflare Tunnel | Несколько студентов проходят квиз одновременно | Изоляция прогресса по 4 фиксированным профилям студентов (`student_id`), режим SQLite WAL |
| Доступ к отладочным ручкам при публичном запуске | `/docs`, `/redoc`, `/api/runner/smoke` | Автоматическое отключение ручек при `PUBLIC_MODE=1` |
