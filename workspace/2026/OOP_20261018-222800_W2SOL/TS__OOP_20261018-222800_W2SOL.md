## 1. Objective

Внедрить в локальную платформу **Web-OOP** полнофункциональный интерактивный модуль **«Неделя 2 · SOLID и DI»** (`/week2`) в стиле **Dark Cyberpunk / Tech Modern** для начинающих студентов, сохранив полную работоспособность и независимость результатов **Недели 1** (`/week1`):
- активный переключатель между `Неделя 1 · Инкапсуляция` (`/week1`) и `Неделя 2 · SOLID и DI` (`/week2`) в шапке платформы и 5 вкладок (`Главная`, `Теория`, `Практика`, `Тестирование`, `Результаты`);
- 3 новые Dark Cyberpunk иллюстрации (`week2_hero.jpg`, `solid_modular.jpg`, `di_ports.jpg`) без мелких Mermaid UML-схем на веб-странице;
- 4 последовательных шага Теории с нуля (`w2_step_1_srp`, `w2_step_2_ocp`, `w2_step_3_lsp_isp`, `w2_step_4_dip_di`) на базе Лекций 4–5 и Лабораторных 4–5;
- построчный разбор готового кода (`WALKTHROUGH_EXAMPLE`) и 3 связанных шага свободного тренажера (`w2_task_1`: `StudentFareService` `100 ₸ / 50 ₸` по SRP; `w2_task_2`: `BluetoothPayment` по OCP/LSP; `w2_task_3`: `TerminalValidator(fare_service, payment_method)` с Constructor DI) с кнопкой «✨ Вставить готовое решение» (`fillSolutionCode`), автопроверкой в `RunnerService` и нулевым требованием баллов (`0.0` б.);
- финальное тестирование Недели 2 из **10 вопросов (`w2_q1`..`w2_q10`) по 2.0 балла = 20.0 баллов** (порог зачета $\ge 12.0$ баллов, High-Water Mark).

## 2. Scope

### In Scope

1. **Образовательный контент Недели 2 (`app/content/week_2/`):**
   - `app/content/week_2/__init__.py`: экспорт `WEEK2_OVERVIEW`, `THEORY_SECTIONS`, `WALKTHROUGH_EXAMPLE`, `PRACTICE_TASKS`, `QUIZ_QUESTIONS`, `get_practice_task`, `evaluate_quiz`.
   - `app/content/week_2/theory.py`:
     - `WEEK2_OVERVIEW` (`week_number: 2`, `max_score: 20.0`, `pass_threshold: 12.0`, `hero_image: "/static/images/week2_hero.jpg"`, 3 шага маршрута с ориентиром `60 + 60 + 60 мин`).
     - `THEORY_SECTIONS`: 4 последовательных шага (`w2_step_1_srp`, `w2_step_2_ocp`, `w2_step_3_lsp_isp`, `w2_step_4_dip_di`) с иллюстрациями `solid_modular.jpg` и `di_ports.jpg`, карточками терминов (`anatomy_cards`) и сравнением `bad_code` vs `good_code`.
     - `WALKTHROUGH_EXAMPLE`: построчный разбор модульного терминала `TerminalValidator`, принимающего сервис тарифа (`100 ₸` / `50 ₸`) и способ оплаты через `__init__` (4 шага разбора).
   - `app/content/week_2/practice.py`:
     - 3 пошаговых упражнения тренажера (`PRACTICE_TASKS`, каждое с `max_score: 0.0`, `starter_code`, `reference_solution`, `hint` и `test_code` для `RunnerService`):
       1. `w2_task_1` (**Шаг 1 из 3 · Принцип S (SRP): Сервис расчета тарифа `100 ₸ / 50 ₸`**): классы `StandardFareService` (`get_fare() -> 100`) и `StudentFareService` (`get_fare() -> 50`), вынесенные из терминала.
       2. `w2_task_2` (**Шаг 2 из 3 · Принципы O и L (OCP & LSP): Бесконтактная оплата `BluetoothPayment` без `if/elif`**): классы `CardPayment` и `BluetoothPayment` с единым контрактом `pay(amount: int) -> str`, возвращающие строку подтверждения оплаты и не выбрасывающие неожиданных ошибок при корректной сумме $> 0$.
       3. `w2_task_3` (**Шаг 3 из 3 · Принцип D (DIP & DI): Сборка `TerminalValidator` через `__init__`**): класс `TerminalValidator(fare_service, payment_method)`, который в методе `process_passenger() -> str` берет сумму у `self.fare_service.get_fare()` и проводит оплату через `self.payment_method.pay(amount)`.
   - `app/content/week_2/quiz.py`:
     - **10 вопросов (`w2_q1`..`w2_q10`)** из согласованного банка `HL §2.2` по **2.0 балла** за каждый правильный ответ (`POINTS_PER_QUESTION = 2.0`, `QUIZ_MAX_SCORE = 20.0`) с подробными объяснениями `explanation` и функцией `evaluate_quiz()`.
2. **Визуальные иллюстрации (`app/static/images/`):**
   - `week2_hero.jpg`, `solid_modular.jpg`, `di_ports.jpg`.
3. **Сервис оценивания и API роутер Недели 2 (`app/services/scoring.py`, `app/routers/week2.py`, `app/routers/week1.py`, `app/main.py`):**
   - Расширение `ScoringService` параметром `week_number: int = 1` (по умолчанию `1` для 100% обратной совместимости с вызовами Недели 1), чтобы прогресс Недели 1 (`week_1`, `week_1_quiz`, `week_1_task_1..3`) и Недели 2 (`week_2`, `week_2_quiz`, `week_2_w2_task_1..3`) хранился в БД независимо с `QUIZ_MAX_SCORE = 20.0`, `PASS_THRESHOLD = 12.0` и защитой High-Water Mark.
   - Роутер `app/routers/week2.py`: `GET /week2`, `GET /api/week2/progress`, `POST /api/week2/practice/{task_id}/run`, `POST /api/week2/quiz/check` и подключение в `app/main.py`.
4. **Фронтенд (`app/templates/index.html`, `app/static/js/app.js`):**
   - Активные кнопки переключения недель в шапке (`Неделя 1 · Инкапсуляция` $\rightarrow$ `/week1` и `Неделя 2 · SOLID и DI` $\rightarrow$ `/week2`) с подсветкой активной недели (`week-pill-active`).
   - Передача `active_week` (`1` или `2`) в `index.html` (`<body data-active-week="{{ active_week|default(1) }}">`) и динамическое обращение `app.js` к `/api/week${activeWeek}/practice/${taskId}/run` и `/api/week${activeWeek}/quiz/check`, а также динамическое обновление карточек задач в `updateProgressUI(progress)`.
5. **Автотесты (`tests/test_week2.py`):**
   - Проверка `GET /week2` (все 5 вкладок, 3 новые иллюстрации `week2_hero.jpg`, `solid_modular.jpg`, `di_ports.jpg`, отсутствие `mermaid.min.js`).
   - Проверка прохождения `reference_solution` всех 3 задач Недели 2 (`w2_task_1`, `w2_task_2`, `w2_task_3`) в `RunnerService` через `POST /api/week2/practice/{task_id}/run` с сохранением `total_score == 0.0`.
   - Проверка квиза Недели 2 (`POST /api/week2/quiz/check`): 10 вопросов, `20.0` баллов при 10/10, зачет при $\ge 12.0$ баллах (6/10), незачет при $10.0$ баллах (5/10), High-Water Mark при повторной слабой попытке, и полная независимость от баллов Недели 1 (`/api/week1/progress`).
