## 1. Objective

Внедрить в мини-LMS Web-OOP модуль **«Неделя 1 · Инкапсуляция»** в стиле **Dark Cyberpunk / Tech Modern**, ориентированный на начинающих студентов: двухуровневая навигация по неделям и 5 вкладкам (`Главная`, `Теория`, `Практика`, `Тестирование`, `Результаты`), пошаговая теория с 3 Cyberpunk-иллюстрациями без мелких Mermaid UML-диаграмм на сайте, свободный практический тренажер без требования баллов с кнопкой подстановки готового решения (`✨ Вставить готовое решение`), и финальное тестирование из **10 вопросов по 2.0 балла = 20.0 баллов** (порог зачета $\ge 12.0$ баллов).

---

## 2. Scope

### In Scope

1. **Образовательный контент (`app/content/week_1/`):**
   - `app/content/__init__.py` и `app/content/week_1/__init__.py`.
   - `app/content/week_1/theory.py`:
     - `WEEK1_OVERVIEW` (`max_score: 20.0`, `pass_threshold: 12.0`, 3 шага маршрута: Теория $\rightarrow$ Практика без оценки $\rightarrow$ Итоговое Тестирование на 20 баллов).
     - `THEORY_SECTIONS`: 4 последовательных шага с нуля (`step_1_problem`, `step_2_blueprint`, `step_3_init_self`, `step_4_encapsulation`) на сквозном классе `SmartCard`.
     - `WALKTHROUGH_EXAMPLE`: построчный разбор взаимодействия классов `Passenger` и `Validator`.
   - `app/content/week_1/practice.py`:
     - 3 связанные пошаговые задачи тренажера (`task_1`, `task_2`, `task_3`) со стартовым шаблоном `starter_code`, подсказками `hint`, эталонным решением `reference_solution` и тестами `test_code`.
   - `app/content/week_1/quiz.py`:
     - **10 вопросов** (`q1`..`q10`) по **2.0 балла** за каждый правильный ответ (`POINTS_PER_QUESTION = 2.0`, `QUIZ_MAX_SCORE = 20.0`) с подробными объяснениями `explanation` и функцией `evaluate_quiz()`.
2. **Визуальные иллюстрации (`app/static/images/`):**
   - `week1_hero.jpg`, `oop_blueprint.jpg`, `oop_encapsulation.jpg`.
3. **Сервис оценивания и API роутер (`app/services/scoring.py`, `app/routers/week1.py`, `app/main.py`):**
   - `ScoringService`: `QUIZ_MAX_SCORE = 20.0`, `TOTAL_MAX_SCORE = 20.0`, `PASS_THRESHOLD = 12.0`. Все 20.0 баллов формируются исключительно из `week_1_quiz` с защитой High-Water Mark. Задачи тренажера (`task_1`, `task_2`, `task_3`) фиксируют только статус прохождения (`is_completed`), не требуя и не начисляя баллов (`score = 0.0`).
   - Эндпоинты: `GET /`, `GET /week1`, `GET /api/week1/progress`, `POST /api/week1/practice/{task_id}/run`, `POST /api/week1/quiz/check`.
4. **Фронтенд в стиле Dark Cyberpunk / Tech Modern (`app/templates/index.html`, `app/static/css/style.css`, `app/static/js/app.js`):**
   - Шапка «ООП · Учебная платформа · Учимся вместе», переключатель недель и 5 вкладок (`Главная`, `Теория`, `Практика`, `Тестирование`, `Результаты`).
   - Вкладка «Практика»: кнопка `✨ Вставить готовое решение` (`fillSolutionCode`), кнопка `💡 Показать текстовую подсказку` и запуск в песочнице.
   - Вкладка «Тестирование»: 10 вопросов с выбором вариантов `A / B / C / D`, расчет до `20.0` баллов (зачет от `12.0` баллов).
5. **Автотесты (`tests/test_week1.py`):**
   - Проверка рендеринга 5 вкладок и иллюстраций на `/` и `/week1`.
   - Проверка прохождения `reference_solution` для всех 3 задач в `RunnerService`.
   - Проверка 10 вопросов квиза на `20.0` баллов (`10 x 2.0`) и порога зачета `12.0` баллов.

### Out of Scope

- Модули Недели 2 (SOLID и DI) и Недели 3 (Паттерны GoF) — отображаются как кнопки со статусом «Скоро».
- Внешние сборщики фронтенда (`npm`, `Vite`, `Webpack`).

## 5. Acceptance Criteria

### AC-1: Единый интерфейс Dark Cyberpunk / Tech Modern и 5 вкладок навигации
На маршрутах `GET /` и `GET /week1` отдается страница «Учебная платформа · Учимся вместе» с переключателем недель (`Неделя 1 · Инкапсуляция`) и 5 вкладками (`Главная`, `Теория`, `Практика`, `Тестирование`, `Результаты`), использующая тему Dark Cyberpunk (`style.css`) и 3 иллюстрации (`/static/images/week1_hero.jpg`, `/static/images/oop_blueprint.jpg`, `/static/images/oop_encapsulation.jpg`).
- [ ] `GET /` и `GET /week1` возвращают HTTP 200 и содержат все 5 вкладок и ссылки на 3 иллюстрации.
- [ ] Старые тесты ядра (`tests/test_health.py`) проходят без ошибок.

Gate: `pytest tests/test_health.py tests/test_week1.py -k "navigation_layout or index_dashboard"`  
Evidence: HTTP-запрос к `GET /` и `GET /week1` через FastAPI `TestClient` / живой сервер с проверкой HTML-ответа и доступности статики.

### AC-2: Пошаговая Теория для новичков и разбор примера `Passenger` / `Validator` [depends: AC-1]
Вкладка «Теория» содержит 4 связанных шага (`step_1_problem` .. `step_4_encapsulation`), а вкладка «Практика» открывается построчным разбором классов `Passenger` и `Validator`.
- [ ] `THEORY_SECTIONS` содержит 4 шага, `WALKTHROUGH_EXAMPLE` содержит код и 4 пояснения по строкам.

Gate: `pytest tests/test_week1.py`  
Evidence: Верификация структуры `THEORY_SECTIONS` и `WALKTHROUGH_EXAMPLE` в рендере страницы.

### AC-3: Свободный тренажер Практики (3 шага `SmartCard`) без требования баллов и с кнопкой готового решения [depends: AC-2]
Вкладка «Практика» содержит 3 связанные задачи (`task_1`, `task_2`, `task_3`), кнопку `✨ Вставить готовое решение` (`fillSolutionCode`), и при запуске через `POST /api/week1/practice/{task_id}/run` проверяет код в `RunnerService`, не начисляя и не требуя баллов (`total_score` остается `0.0`).
- [ ] Все 3 эталонных решения (`reference_solution`) проходят `RunnerService.run_code` со статусом `PASSED`.
- [ ] После прохождения всех 3 задач тренажера `tasks_completed == 3`, а `total_score == 0.0`.

Gate: `pytest tests/test_week1.py -k "practice"`  
Evidence: Вызов `POST /api/week1/practice/task_1..3/run` и проверка ответа JSON (`passed: true`, `total_score: 0.0`).

### AC-4: Итоговое Тестирование в конце недели на 20.0 баллов (10 вопросов $\times$ 2.0 балла) [depends: AC-3]
Вкладка «Тестирование» содержит 10 вопросов (`QUIZ_QUESTIONS`), каждый правильный ответ дает `2.0` балла (`max_score = 20.0`, порог зачета `pass_threshold = 12.0`). Результат сохраняется в SQLite с защитой High-Water Mark.
- [ ] `len(QUIZ_QUESTIONS) == 10`, при всех верных ответах `POST /api/week1/quiz/check` возвращает `score == 20.0`, `total_score == 20.0`, `is_completed == True`, `progress_percent == 100`.
- [ ] При 6 верных ответах из 10 начисляется `12.0` баллов (`is_completed == True`), а последующая отправка с меньшим числом верных ответов не снижает сохраненный балл (High-Water Mark).

Gate: `pytest tests/test_week1.py -k "quiz"`  
Evidence: Вызов `POST /api/week1/quiz/check` и `GET /api/week1/progress` с проверкой персистентности в БД.

### AC-5: Чистота линтера и прохождение всего тестового набора [depends: AC-4]
Все модули проекта проходят проверку `ruff check .` и полный прогон `pytest`.
- [ ] `ruff check .` возвращает `All checks passed!`.
- [ ] `pytest` возвращает `20 passed`.

Gate: `ruff check . && pytest`  
Evidence: Полный вывод `ruff check .` и `pytest -v`.
