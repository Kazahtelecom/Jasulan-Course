## 1. Objective

Разработать и протестировать самодостаточный инженерный каркас мини-LMS для изучения ООП: бэкенд на FastAPI, база данных SQLite на SQLAlchemy 2.0, Zero-Build фронтенд (Tailwind CDN, Vanilla JS, Mermaid.js) и безопасная песочница запуска тестов RunnerService с полной документацией в `docs/`.

---

## 2. Scope

### In Scope

1. **Конфигурация окружения и зависимостей (`pyproject.toml`):**
   - Установка и фиксация: `fastapi`, `uvicorn[standard]`, `sqlalchemy>=2.0`, `pydantic>=2.0`, `jinja2`, `pytest`, `pytest-asyncio`, `httpx`, `ruff`.
2. **База данных (`app/database/`, `app/models/`):**
   - Файл SQLite по пути `data/web_oop.db` (каталог `data/` создается при инициализации).
   - Базовый DeclarativeBase и генератор сессий `get_db`.
   - Модели:
     - `Student`: `id` (int/str), `username` (unique), `full_name`, `created_at`.
     - `TopicProgress`: `id`, `student_id`, `topic_id`, `is_completed`, `score`, `updated_at`.
     - `Submission`: `id`, `student_id`, `task_id`, `code`, `status`, `test_output`, `created_at`.
3. **Песочница кода (`app/services/runner.py`, `app/services/ast_validator.py`):**
   - Статический AST-анализ: запрет модулей `os`, `sys`, `subprocess`, `shutil`, `socket`, а также встроенных функций `eval`, `exec`, `__import__`.
   - Изолированное исполнение во временной директории (`tempfile.TemporaryDirectory`).
   - Запуск `pytest` через `subprocess.run` с жестким ограничением времени: `timeout=5.0` секунд.
   - Сбор структурированного отчета: статус выполнения (`PASSED`, `FAILED`, `TIMEOUT`, `SECURITY_VIOLATION`), stdout/stderr, время исполнения в мс.
4. **Контроллеры и транспорт (`app/routers/`, `app/main.py`):**
   - `GET /api/health`: JSON со статусом сервера, доступности SQLite и готовности песочницы.
   - `POST /api/runner/smoke`: запуск эталонного теста в песочнице и возврат времени/статуса.
   - `GET /`: отдача дашборда каркаса.
   - Монтирование `/static` каталога.
5. **Zero-Build фронтенд (`app/templates/index.html`, `app/static/`):**
   - Подключение Tailwind CSS через CDN (`https://cdn.tailwindcss.com`).
   - Подключение Mermaid.js через CDN (`https://cdn.jsdelivr.net/npm/mermaid/dist/mermaid.esm.min.mjs`).
   - Модульный Vanilla JS (`app/static/js/app.js`): опрос `/api/health`, отправка запроса на `/api/runner/smoke` с визуализацией результата.
   - Отображение 3 индикаторов статусов («Бэкенд: Active», «SQLite: Connected», «Runner: Ready»).
   - Кнопка «Smoke-тест раннера» с динамической обратной связью (бейдж, задержка, лог).
   - Автоматический рендеринг Mermaid-диаграммы классов `Passenger` и `Validator` предметной области Avtobys.
6. **Документация (`docs/`):**
   - `docs/architecture.md`: описание слоев Clean Architecture, потоков данных, механизма RunnerService и безопасности.
   - `docs/domain_model_uml.md`: UML-диаграммы классов Avtobys и ER-диаграмма сущностей базы данных.
7. **Тестирование и контроль качества (`tests/`):**
   - Юнит-тесты на эндпоинты FastAPI (`tests/test_health.py`).
   - CRUD-тесты моделей SQLAlchemy (`tests/test_models.py`).
   - Тесты песочницы RunnerService (`tests/test_runner.py`): успешный запуск, таймаут 5с, AST-блокировка.
   - Соответствие линтеру `ruff check .`.

### Out of Scope

- Учебные материалы Недели 1 (лекции, тексты задач, банк квизов) — строго следующая задача.
- Авторизация студентов через пароли / OAuth / JWT (в каркасе используется студент по умолчанию).
- Использование любых npm-пакетов, `package.json`, Vite, Webpack (Zero-Build принцип).
- Контейнеризация Docker (проект оптимизирован для локального прямого запуска).

## 5. Acceptance Criteria

### AC-1: FastAPI Server & Health API
Приложение FastAPI запускается через Uvicorn, монтирует статические файлы и возвращает корректный статус компонентов.
- [ ] `GET /api/health` возвращает HTTP 200 и JSON: `{"status": "ok", "db": "connected", "runner": "ready"}`.
- [ ] Точка входа `app/main.py` инициализирует таблицы базы данных при старте.
- [ ] Документация Swagger UI доступна по адресу `http://localhost:8000/docs`.

Gate: `pytest tests/test_health.py -v`  
Evidence: Запуск сервера и curl/httpx проверка `/api/health` с кодом ответа 200.

### AC-2: Database Layer & Models
SQLite база данных инициализируется в `data/web_oop.db`, таблицы создаются автоматически.

- [ ] Сессия `get_db` корректно открывается и закрывается.
- [ ] Корректно выполняются операции создания и чтения записей всех трех моделей.

Gate: `pytest tests/test_models.py -v`  
Evidence: Проверка наличия созданного файла `data/web_oop.db` и успешный прогон тестов моделей.

## 6. Technical Guidance

- Использовать `async with lifespan(app)` в `app/main.py` для создания таблиц `Base.metadata.create_all(bind=engine)` при старте.
- В `app/services/runner.py` запускать `pytest` через `sys.executable -m pytest test_solution.py` внутри временного каталога, чтобы использовать интерпретатор текущего виртуального окружения.
- Использовать `capture_output=True, text=True` в `subprocess.run`, а также перехватывать `subprocess.TimeoutExpired`.
- Для Tailwind CSS и Mermaid.js использовать надежные CDN-ссылки, указанные в Scope.

## 7. Definition of Failure

- ❌ Появление `package.json`, `node_modules` или инструментов сборки фронтенда.
- ❌ Добавление контента Недели 1 в этот релиз.
- ❌ Пробитие песочницы (выполнение `os.system` или зависание процесса более чем на 5.5 секунд).
- ❌ Падение любого из тестов сьюта `pytest` или наличие замечаний `ruff`.
- ❌ Отсутствие документов `docs/architecture.md` или `docs/domain_model_uml.md`.

## 8. Phase Risks

| Risk | Mitigation |
|---|---|
| Блокировка временных файлов под Windows при удалении `TemporaryDirectory` | Использовать конструкцию `try...finally` и принудительно завершать дочерний процесс перед удалением каталога. |
| Ложные срабатывания AST на легитимных ООП-конструкциях | Запрещать только конкретные модули и глобальные вызовы `eval`/`exec`, разрешая любые объявления классов, методов, типов и свойств. |
