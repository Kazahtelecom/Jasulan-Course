## 1. Understanding

Задача заключается в реализации надежного, самодостаточного и легковесного платформенного каркаса локальной мини-LMS на базе FastAPI, базы данных SQLite с SQLAlchemy 2.0, Zero-Build веб-интерфейса (Tailwind CSS CDN, Vanilla JS, Mermaid.js CDN) и изолированной песочницы тестирования студенческого кода RunnerService с предварительным AST-анализом безопасности и жестким лимитом времени 5 секунд. Каркас создается как фундаментальная база для последующего добавления учебных модулей по ООП (начиная с Недели 1 в следующей задаче).

## 2. Entry Points

- `pyproject.toml` — фиксация зависимостей Python (`fastapi`, `uvicorn[standard]`, `sqlalchemy>=2.0`, `pydantic>=2.0`, `jinja2`, `pytest`, `pytest-asyncio`, `httpx`, `ruff`).
- `app/main.py`, `app/config.py` — инициализация FastAPI, монтирование статики, создание таблиц БД при старте (lifespan) и подключение роутеров.
- `app/database/` (`base.py`, `session.py`) — настройка движка SQLite и сессий.
- `app/models/` (`student.py`, `progress.py`, `submission.py`) — сущности БД на SQLAlchemy 2.0 (`Mapped`, `mapped_column`).
- `app/services/` (`runner.py`, `ast_validator.py`) — бизнес-логика AST-безопасности и изолированного запуска `pytest` во временной директории.
- `app/routers/` (`health.py`, `runner.py`) — эндпоинты `/api/health` и `/api/runner/smoke`.
- `app/templates/index.html`, `app/static/js/app.js`, `app/static/css/style.css` — дашборд со статусами, smoke-кнопкой и Mermaid-диаграммой домена Avtobys.
- `docs/` (`architecture.md`, `domain_model_uml.md`) — архитектурная и доменная документация.
- `tests/` (`conftest.py`, `test_health.py`, `test_models.py`, `test_runner.py`) — полный набор автотестов.

*Обязательства базовой линии:* Сохраняются все утвержденные границы (отсутствие `package.json`/`node_modules`, отсутствие учебных материалов Недели 1, лимит 5с на выполнение тестов). Временные ресурсы: каталог временных файлов песочницы создается через `tempfile.TemporaryDirectory` и детерминированно удаляется после завершения прогона тестов в блоке `finally`.

## 4. Recommendations (suggestions, not blocking)

1. В `app/services/runner.py` запускать `pytest` через `sys.executable -m pytest` для гарантированного использования текущего виртуального окружения Python.
2. В блоке `finally` удаление каталога `TemporaryDirectory` обернуть с обработкой возможных задержек отпускания дескрипторов файлов процессами под Windows (`ignore_cleanup_errors=True` в Python 3.10+).

## 5. Risks Found (edge cases, potential issues not in TS)

1. Блокировка дескрипторов файлов в Windows: дочерний процесс `python` может не сразу отпустить файл теста при таймауте. Смягчение: принудительный `kill()` и `communicate()` перед удалением каталога.

## 6. Inconsistencies with Code (spec vs reality)

1. Репозиторий находится в состоянии Greenfield (чистый старт). Кодовая база приложения отсутствует, расхождений с кодом нет.
