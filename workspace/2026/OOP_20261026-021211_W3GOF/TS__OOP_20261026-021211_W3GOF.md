## 1. Objective

**Goal:** Интегрировать заключительный учебный модуль **Недели 3 («Паттерны проектирования GoF и Чистая Архитектура»)** на сквозном домене транспортной системы **Avtobys** в платформу Web-OOP (`/week3` и `/api/week3/...`) по материалам авторских Лекций 6–9 и Лабораторных 6–9 (`C:\Users\kz444\OneDrive\Desktop\OOP`).

**Delivered Value:** Студенты 2 курса получают полностью рабочий 3-й недельный цикл обучения ООП:
1. **4 пошаговых раздела теории (`THEORY_SECTIONS`) и построчный разбор кода (`WALKTHROUGH_EXAMPLE`)** с карточками анатомии, примерами «Плохо / Хорошо» и 3 Cyberpunk-иллюстрациями (`/static/images/week3_hero.jpg`, `/static/images/gof_patterns.jpg`, `/static/images/clean_arch_layers.jpg`).
2. **Интерактивную векторную UML-диаграмму Недели 3 (`#svg-week3`)** с собственным изолированным блоком `<defs>`, лупой 2.5× и полноэкранным зумом, наглядно связывающую паттерны GoF и 4 слоя Clean Architecture (`The Dependency Rule`).
3. **3 задачи свободного IDE-тренажёра (`w3_task_1`, `w3_task_2`, `w3_task_3`, `max_score: 0.0`)** с кнопкой «Показать готовое решение» (`reference_solution`), протестированные в нативной песочнице `RunnerService` (`ASTValidator` + `python -I -m pytest`).
4. **10 сбалансированных вопросов итогового теста (`w3_q1..w3_q10`, `20.0` баллов, порог зачёта `12.0` баллов)** с защитой от угадывания (`min_len >= 60`, `max_len / min_len <= 1.65`, равномерное распределение `correct_index` по 2–3 раза на `0..3`, не менее 5 из 10 правильных ответов не являются строго самыми длинными) и изолированным хранением прогресса 4 студентов в SQLite WAL.

1. **Точные сигнатуры 3 задач тренажёра (`app/content/week_3/practice.py`, конфигурация `C3` из `3_extract.md` `E2`):**
   - **Задача 1 (`w3_task_1` — Лаб 6 `ShiftReportBuilder` + Лаб 7 `BankApiAdapter`):**
     - `@dataclass(frozen=True) class DailyShiftReport`: `route_id: str`, `driver_id: str`, `total_revenue: Decimal`, `incidents: tuple[str, ...] = ()`.
     - `class IncompleteReportError(ValueError): pass`
     - `class ShiftReportBuilder`: методы `set_shift_info(self, route_id: str, driver_id: str) -> "ShiftReportBuilder"`, `add_qr_revenue(self, amount: Decimal) -> "ShiftReportBuilder"`, `record_incident(self, description: str) -> "ShiftReportBuilder"`, `build(self) -> DailyShiftReport` (выбрасывает `IncompleteReportError`, если `not self._route_id or not self._driver_id`).
     - `class LegacyBankClient`: `execute_payment_kzt(self, source_pan: str, dest_account: str, amount_tiyn: int) -> dict` (возвращает `{"auth_code": f"AUTH-{source_pan}-{amount_tiyn}"}`).
     - `class BankApiAdapter`: `__init__(self, external_client: LegacyBankClient, transit_account: str)` и `charge(self, card_id: str, amount: Decimal) -> str` (переводит тенге в тиыны `int(amount * 100)`, вызывает `execute_payment_kzt` и возвращает `res["auth_code"]`).
   - **Задача 2 (`w3_task_2` — Лаб 8 `ValidationHandler` Chain of Responsibility + `TransitTelemetrySubject` Observer):**
     - `@dataclass class PaymentRequest`: `card_id: str`, `balance: Decimal`, `fare: Decimal`, `blacklisted_cards: set[str] = field(default_factory=set)`.
     - `@dataclass(frozen=True) class ValidationResult`: `is_approved: bool`, `reason: str = "OK"`.
     - `class ValidationHandler(ABC)`: `set_next(self, handler: "ValidationHandler") -> "ValidationHandler"`, `handle(self, request: PaymentRequest) -> ValidationResult` (по умолчанию передаёт следующему обработчику или возвращает `ValidationResult(is_approved=True, reason="OK")`).
     - `class BlacklistCheckHandler(ValidationHandler)`: при `request.card_id in request.blacklisted_cards` возвращает `ValidationResult(is_approved=False, reason="Карта в черном списке")`, иначе `super().handle(request)`.
     - `class BalanceCheckHandler(ValidationHandler)`: при `request.balance < request.fare` возвращает `ValidationResult(is_approved=False, reason="Недостаточно средств")`, иначе `super().handle(request)`.
     - `class TransitTelemetrySubject`: `attach(self, observer) -> None`, `detach(self, observer) -> None`, `notify(self, event: str) -> None` (вызывает `observer.update(event)` для всех активных подписчиков без использования `.__class__.__name__`).
   - **Задача 3 (`w3_task_3` — Лаб 9 `Clean Architecture` Use Case):**
     - `@dataclass(frozen=True) class Money`: `amount: Decimal`, `currency: str = "KZT"`.
     - `@dataclass class TransitCard`: `card_id: str`, `balance: Decimal`, метод `charge_fare(self, fare: Money) -> None` (при `self.balance < fare.amount` выбрасывает `ValueError("Insufficient funds")`, иначе уменьшает `self.balance -= fare.amount`).
     - `@dataclass(frozen=True) class ValidateRideRequest`: `card_id: str`, `fare_amount: Decimal`.
     - `@dataclass(frozen=True) class ValidateRideResponse`: `success: bool`, `remaining_balance: Decimal`, `tx_id: str`.
     - `class ValidateRideUseCase`: `__init__(self, card_repo, payment_gateway)` и `execute(self, request: ValidateRideRequest) -> ValidateRideResponse` (1. `card = self._card_repo.get_by_id(request.card_id)`, 2. `fare = Money(request.fare_amount)`, 3. `card.charge_fare(fare)`, 4. `tx_id = self._payment_gateway.charge(card.card_id, fare.amount)`, 5. `self._card_repo.save(card)`, 6. возвращает `ValidateRideResponse(success=True, remaining_balance=card.balance, tx_id=tx_id)`).
