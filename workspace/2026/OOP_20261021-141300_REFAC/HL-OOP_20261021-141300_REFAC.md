- [`app/services/runner.py`](../../../app/services/runner.py): `subprocess` с правами сервера, таймаут и временная папка, без лимитов памяти и CPU, с унаследованным окружением. Подлежит изоляции.
- `run_public.bat` публикует сервер через Cloudflare Tunnel (`trycloudflare.com`, RES FC2); авторизации на `/api/*` нет; `/docs` открыт; ручки `/docs`, `/redoc` и `/api/runner/smoke` требуют закрытия на публичном запуске (RES D6).
- `index.html` (607 строк) и `app.js` (347 строк) — монолиты с ветвлениями по неделям (RES H2). XSS через вывод кода опровергнут: вывод экранируется через `textContent`. Решение: декомпозиция на Jinja include-компоненты по вкладкам (RES D4).
- Роутеры `week1.py` и `week2.py` дублируют 80% кода и логики (RES H1). Необходим общий контракт `WeekModule` и единый реестр недель (RES D1).
- В коде недель 1 и 2 отсутствует отметка о прочтении теории (требование преподавателя, RES D5). Реализуется через топик прогресса `week_N_theory` без изменения схемы БД.
- При GET-запросах к API прогресса происходит вызов `commit` в БД (мутация при чтении).
- Все запросы сейчас работают под одним зашитым студентом `zhasulan`: при публичном туннеле это приводит к затиранию баллов. Решение: выбор профиля из 4 фиксированных участников группы (RES D3).
- 24 существующих теста покрывают только позитивные сценарии и базовый синтаксис (RES H3). Необходим сьют негативных тестов (HTTP 422, пустые пейлоады, лимиты, невалидные типы).
- Баг «10 failed = 10/10» из замечаний преподавателя относится к репозиторию другого студента и в объём не входит (подтверждено владельцем).
- Собственные UML-диаграммы проекта лежат в [`docs/domain_model_uml.md`](../../../docs/domain_model_uml.md) и [`docs/architecture.md`](../../../docs/architecture.md); подлежат синхронизации с кодом после рефакторинга.
- Незафиксированные файлы `Dockerfile` и `docker-compose.yml` являются черновиками и не требуются для работы на хосте без Docker; `run_public.bat` должен быть внесен в `.gitignore` (или очищен от секретов).

## 6. Definition of Failure (DoF) 🔒 FROZEN
- ❌ 1. Рефакторинг изменил видимое поведение недель 1–2 или сломал существующие тесты без согласованной причины.
- ❌ 2. После работы дублирование между неделями осталось или появилось новое, либо структура требует копирования кода для недели 3.
- ❌ 2а. Безопасность входит в список, и хотя бы одна обходная попытка из DoD 4б выполняет действие на хосте.
- ❌ 3. Аудит проверял состояние, содержащее незавершённые или незафиксированные изменения кода недель 1–2 без указания этого в RES.
- ❌ 4. Изменения вышли за утверждённый владельцем список без поправки.

**On failure:** остановка, откат фазы к последнему рабочему коммиту, возврат владельцу с причиной.

## 7. Principles 🔒 FROZEN
1. **Чистота прежде всего** — одна сущность, одна зона ответственности; код не дублируется; диаграммы отражают код.
1а. **Изоляция вместо фильтрации** — если безопасность входит в список, защита не опирается на перечень запрещённого.
2. **Сначала измерить, потом чинить** — работа по списку из RES, а не по догадкам.
3. **Чистая база** — аудит проверяет зафиксированное состояние репозитория; незафиксированные изменения указываются в RES.
4. **Не ломать студента** — видимое поведение недель 1–2 сохраняется.
5. **Минимально достаточное** — не добавлять инфраструктуру сверх закрытия найденных рисков.
