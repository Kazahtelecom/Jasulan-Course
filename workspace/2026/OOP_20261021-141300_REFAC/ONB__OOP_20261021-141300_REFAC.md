## 1. Understanding

Задача заключается в проведении комплексного рефакторинга платформы Web-OOP для подготовки к добавлению образовательного контента Недели 3 (Паттерны GoF). Необходимо:
1. Устранить ~80% дублирования между роутерами Недели 1 и 2, создав модульный контракт `WeekModule` и единый реестр `WeekRegistry`, чтобы Неделя 3 и последующие недели подключались декларативно без копирования маршрутов и обработчиков.
2. Декомпозировать монолитные файлы фронтенда: разбить `app/templates/index.html` (607 строк) на Jinja `include`-компоненты по вкладкам (`header`, `home`, `theory`, `practice`, `quiz`, `results`) и модулировать `app/static/js/app.js` (347 строк).
3. Обеспечить безопасность выполнения студенческого кода в тренажере: заменить черный список на строгий синтаксический белый список AST (разрешен только учебный синтаксис ООП, запрещены системные атрибуты `__class__`, `__subclasses__`, `__builtins__` и функции вроде `open`, `eval`, `importlib`), изолировать процесс через `python -I` во временной папке с лимитом размера кода 15 КБ и таймаутом, без привязки к Docker.
4. Реализовать требования преподавателя и владельца: добавить переключатель 4 предопределенных профилей студентов (`Zhasulan`, `Roman`, `Arseniy`, `Saubakirov`) с изолированным сохранением баллов в SQLite, добавить кнопку подтверждения прочтения лекции в конце теории (`week_N_theory`), исключить нежелательные мутации (`commit`) базы при GET-запросах чтения прогресса, закрыть отладочные ручки при публичном запуске и занести `run_public.bat` в `.gitignore`.
5. Обеспечить строгое тестовое покрытие: разработать тесты безопасности песочницы (`tests/test_sandbox_security.py`), негативные тесты API (`tests/test_negative_cases.py`), тесты контракта модулей и многопользовательского режима (`tests/test_week_modules.py`), сохранив 100% работоспособность всех 24 существующих тестов.
6. Актуализировать UML-диаграммы в `docs/domain_model_uml.md` и архитектурное описание в `docs/architecture.md`.

## 5. Risks Found (edge cases, potential issues not in TS)

1. **Разбиение шаблонов Jinja**: При выносе в `app/templates/components/` важно точно сохранить все существующие HTML-идентификаторы (`id="btn-run-code"`, `id="editor"`, `id="results-content"` и т.д.), чтобы логика `app.js` не потеряла привязки к элементам интерфейса.
2. **Лимит размера кода**: Проверка размера кода (15 КБ) должна проводиться до парсинга AST, чтобы исключить DoS через синтаксический анализ гигантских файлов.

## 6. Inconsistencies with Code (spec vs reality)

1. В текущей реализации `ScoringService` жестко зашит единственный студент `zhasulan` и отсутствует сущность профиля; добавление селектора 4 профилей требует параметризации методов подсчета без изменения таблицы `TopicProgress` (поскольку `topic_id` уже включает контекст, а имя студента передается в заголовке или параметрах).
2. В роутере `app/routers/scoring.py` эндпоинты чтения прогресса вызывают методы, внутри которых происходил `db.commit()` — требуется разделить read-only получение и сохранение результатов.
