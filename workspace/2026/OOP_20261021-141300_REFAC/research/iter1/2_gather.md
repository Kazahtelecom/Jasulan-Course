## Findings

### G1: Структура и дублирование (код, `HEAD`)
- [`app/routers/week1.py`](../../../../app/routers/week1.py) (132 строки) и [`week2.py`](../../../../app/routers/week2.py) (134 строки) структурно совпадают: одинаковые `CodeSubmissionRequest`, `QuizSubmissionRequest`, `Jinja2Templates`, обработчики `progress`, `practice/{task_id}/run`, `quiz/check`; различаются имена контекста, импорты `content.week_N`, префикс URL и параметр `week_number=2`. По построчному сравнению (`Compare-Object`) различий 50 записей, то есть около 25 строк с каждой стороны из ~133 (≈ 20% файла), остальное повторено.
- Пакеты контента `app/content/week_1` и `week_2` имеют одинаковую форму: `theory.py` (276 и 354 строки), `quiz.py` (205 и 241), `practice.py` (270 и 271), `__init__.py` с одним и тем же набором экспортов; `evaluate_quiz` и `get_practice_task` есть в обоих и не совпадают дословно (требует построчной проверки в Extract).
- [`app/main.py`](../../../../app/main.py) рендерит `/` через `week1.build_platform_context`: корневой маршрут зависит от роутера недели 1.
- [`scoring.py`](../../../../app/services/scoring.py): `WEEK_TASK_IDS` задаёт идентификаторы заданий только для недель 1 и 2 (`task_1..3`, `w2_task_1..3`); `get_progress_summary` для неизвестной недели молча подставляет неделю 1. Константы `TOPIC_OVERALL`, `TOPIC_TASK_1..3`, `TOPIC_QUIZ` относятся к неделе 1 и, по первому чтению, не используются в формировании ключей (ключи строятся f-строкой `week_{n}_...`). Сервис совмещает три роли: профиль студента, запись отправок, расчёт и сводка баллов.
- Операции чтения меняют БД: `get_progress_summary` вызывает `_get_or_create_topic`, `_recalculate_overall` и `db.commit()` при `GET /api/weekN/progress` и при рендере страниц.

### G2: Фронтенд
- [`index.html`](../../../../app/templates/index.html): 607 строк, одна страница из пяти панелей (`home`, `theory`, `practice`, `quiz`, `results`) и три блока `{% if active_week == 2 %}…{% else %}` (строки 193–203, 307–311, 335–339 плюс вложенные условия), где неделя 2 вшита в шаблон. Для недели 3 понадобится ещё один `elif` в каждом месте.
- [`app.js`](../../../../app/static/js/app.js): 347 строк, один файл, глобальные функции; функция `submitWeek1Quiz` обслуживает обе недели; константа `12.0` порога зачёта продублирована в JS и в `ScoringService.PASS_THRESHOLD`; текст «6 правильных ответов из 10» зашит в строку.
- XSS (H2): `|safe` и `Markup` в шаблоне и контенте отсутствуют; HTML-тегов в `theory.py` нет; пользовательский вывод (`data.output`) вставляется через `textContent`. Единственные `innerHTML` с данными — `${item.explanation}` и баннер результата; `explanation` берётся из серверного контента, а не от студента. Предварительно: XSS по студенческим данным не обнаружен; статус требует проверки в Extract (рендер ответа теста).

### G3: Запуск кода и AST-валидатор (H4)
- [`ast_validator.py`](../../../../app/services/ast_validator.py): проверяются только `Import`/`ImportFrom` для модулей `os`, `sys`, `subprocess`, `shutil`, `socket` и вызовы по имени `eval`, `exec`, `__import__` (`ast.Name`). Не покрыты по построению: `importlib`, `ctypes`, `pathlib`, `builtins`, `open`, `getattr`/`__builtins__`, цепочки `__class__.__bases__[0].__subclasses__()`, сборка имён из строк, `compile`, `os` через `__import__`-подобные пути. `KNOWLEDGE.md` F4 перечисляет только `eval` и `exec` (код блокирует и `__import__`): F4 отстаёт от кода.
- [`runner.py`](../../../../app/services/runner.py): `subprocess.run([sys.executable, "-m", "pytest", ...], cwd=tmp, capture_output, timeout=5)` без `env`, без `-I`, без лимитов памяти и процессов, без запрета сети. Процесс наследует права и окружение пользователя, запустившего `uvicorn`. По таймауту убивается только прямой процесс (`subprocess.run` не завершает потомков).
- Внешние источники (вторичные сводки, проверяются эмпирически в Extract): Python-песочницы на чёрных списках и AST «структурно недостаточны», обходы через `__subclasses__`, `getattr`, сборку строк (checkmarx.com, huntr.com, github.com); для недоверенного кода рекомендуются процессные или контейнерные границы (safeguard.sh, modal.com). Hardened-запуск Docker: `--network none`, `--memory`, `--cpus`, `--pids-limit`, `--read-only`, `--cap-drop ALL`, `no-new-privileges`, пользователь без root, `tmpfs` с `noexec`; контейнеры делят ядро хоста, для враждебного кода упоминаются gVisor и Kata (dev.to, modal.com). Windows Job Object через `pywin32`: лимиты `PROCESS_MEMORY`, `PROCESS_TIME`, `KILL_ON_JOB_CLOSE`, запуск в приостановленном состоянии (`CREATE_SUSPENDED`) и назначение процесса в Job до старта (stackoverflow.com, microsoft.com); Job Object не запрещает чтение файлов и сеть сам по себе.
- На машине владельца: Python 3.12.9, `pytest` 9.1.1, `fastapi` 0.143.1, `SQLAlchemy` 2.1.4. `docker` не найден в PATH (`CommandNotFoundException`); `pywin32` и `pytest-cov` не установлены.

### G4: Эксплуатация и публичный доступ
- [`run_public.bat`](../../../../run_public.bat) (не в git): запускает `uvicorn app.main:app --host 127.0.0.1 --port 8000` и `cloudflared tunnel --url http://127.0.0.1:8000` (quick tunnel `trycloudflare.com`, без Cloudflare Access). Любой, у кого есть ссылка, получает доступ ко всем маршрутам: сервер слушает только localhost, но туннель публикует его целиком. `cloudflared.exe` скачивается из `releases/latest` без проверки подписи или хеша.
- Владелец подтвердил, что студенты заходят через публичный сайт, а `run_public.bat` он запускает сам. Сервер работает под учётной записью владельца: студенческий код выполняется с её правами (файлы `OneDrive`, `data/web_oop.db`, ключи, история браузера).
- [`main.py`](../../../../app/main.py): `docs_url="/docs"`, `redoc_url="/redoc"` открыты; `/api/runner/smoke` доступен без авторизации. В `config.py` нет настроек CORS, лимитов и авторизации.
- Валидация входа: `CodeSubmissionRequest.code: str` без `max_length`; `QuizSubmissionRequest.answers: dict[str, int]` без ограничений ключей и размера. `Submission.code` — `Text` без ограничения: каждый запуск пишет код и вывод в SQLite (рост БД). Признаков ограничения частоты запросов не найдено.
- Требование преподавателя «отметка о прочтении лекции»: в коде и шаблоне не найдено полей, маршрутов или модели (поиск по `прочит`, `is_read`, `read_at`). Предварительно: функция отсутствует.
- Незафиксированные файлы: `Dockerfile` выполняет `pip install -e .` до копирования `app/` (возможная ошибка сборки, `pyproject.toml` не проверялся) и копирует `README.md`, а `docker-compose.yml` публикует `8000:8000` на всех интерфейсах с томом `./data:/app/data`; `docker` на машине владельца не установлен, так что варианты не запускались. Правка `README.md` — смена ссылки на задачу, а не набросок архитектуры.
- `.gitignore` не содержит `run_public.bat`; `data/` не отслеживается, `*.db` игнорируется.
