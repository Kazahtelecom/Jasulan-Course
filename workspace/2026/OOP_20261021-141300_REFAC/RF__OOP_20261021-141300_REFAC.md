## 2. Key Decisions

1. **`WeekModule` и единый реестр недель:** Вместо дублирования роутеров для каждой новой недели создан контракт `WeekModule` и реестр `WeekRegistry`. Неделя 3 подключится декларативно без изменения транспортного слоя.
2. **AST Whitelist вместо черного списка:** Защита тренажера гарантируется строгим белым списком AST-узлов и модулей, блокировкой атрибутов `__class__`, `__subclasses__`, `__builtins__`, вызовов `open`, `eval`, `getattr`, лимитом размера кода 15 КБ и изолированным режимом `python -I`. Решение не требует Docker Desktop и стабильно работает на Windows хосте владельца.
3. **Изоляция 4 профилей студентов:** Переключатель 4 студентов (`Zhasulan`, `Roman`, `Arseniy`, `Saubakirov`) в UI с передачей через `X-Student-Id` полностью устранил проблему затирания баллов при публичном туннеле без усложнения инфраструктуры паролями.
4. **Устранение мутаций при чтении:** Эндпоинты `GET /api/week{N}/progress` и `/api/students/scores` переведены в строго read-only режим (без вызова `db.commit()`).
5. **Отметка теории:** Добавлен топик `week_N_theory` и кнопка подтверждения прочтения в конце теории, закрывающая требование преподавателя.
